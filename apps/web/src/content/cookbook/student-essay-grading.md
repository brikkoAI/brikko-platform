# AI-проверка эссе с обоснованием оценки

## Зачем это нужно

В edtech-платформе с курсами по soft-skills, маркетингу или языкам преподаватель должен проверить 200-500 эссе в неделю. На каждое — 5-10 минут чтения и обоснования оценки. Курс с 1 000 студентами и одним заданием в неделю даёт 4 000 работ в месяц, и это становится узким горлышком: либо нанимать ассистентов на проверку (50-100к ₽/мес каждому), либо снижать частоту заданий.

LLM-проверка не заменяет преподавателя, но решает 80% работ за 90% стоимости: модель ставит черновую оценку и пишет обоснование по рубрике, преподаватель валидирует, спорные кейсы (расхождение с собственной интуицией ±2 балла) перепроверяет вручную. Время на ревью одного эссе падает с 7 до 2 минут.

## Какая модель и почему

**GPT-5.4** — лучше держит структуру при сложных рубриках (5-7 критериев, каждый со своим весом), даёт обоснование на конкретные предложения текста, реже хвалит «вообще». Для русскоязычных эссе на 200-800 слов точность совпадения с экспертной оценкой ±1 балл по 10-балльной шкале — около 78-82%.

С автоматическим failover на **Claude Sonnet 4.6**, если OpenAI вернёт ошибку или окажется недоступен. Brikko делает это прозрачно: указываешь `failover` в headers, получаешь ответ от резервного провайдера без изменений в коде.

Дешевле — Gemini 3 Flash (в 5 раз). Хуже структура и более «общие» комментарии, но для массовой проверки коротких эссе (до 200 слов) сойдёт.

## Готовый код

```python
from openai import OpenAI
import json

client = OpenAI(
    api_key="brk_live_...",
    base_url="https://api.brikko.ru/v1",
)

RUBRIC = """
Критерии (каждый 1-10):
1. Структура и логика (intro/body/conclusion, связки).
2. Аргументация (есть ли тезис, поддерживают ли его аргументы).
3. Примеры и факты (конкретика vs общие фразы).
4. Язык и стиль (грамматика, словарный запас, тон).
5. Соответствие теме.

Итоговая оценка = среднее.
"""

SYSTEM_PROMPT = f"""Ты проверяешь эссе студентов по следующей рубрике.

{RUBRIC}

Для каждого критерия:
- оценка 1-10;
- 1-2 предложения обоснования с цитатой из эссе;
- одно конкретное предложение, как улучшить.

Формат ответа — JSON:
{{
  "scores": {{"structure": int, "argument": int, "examples": int, "language": int, "topic": int}},
  "feedback": {{"structure": "...", "argument": "...", ...}},
  "improvements": {{"structure": "...", ...}},
  "overall": float,
  "summary": "2-3 предложения общего фидбэка студенту"
}}
"""

def grade_essay(topic: str, essay: str) -> dict:
    response = client.chat.completions.create(
        model="gpt-5-4",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": f"Тема:\n{topic}\n\nЭссе:\n{essay}"},
        ],
        response_format={"type": "json_object"},
        temperature=0.3,
        max_tokens=1200,
        extra_headers={
            "X-Brikko-Failover": "claude-sonnet-4-6",
        },
    )
    return json.loads(response.choices[0].message.content)
```

## Примеры

**Кейс 1. Слабое эссе:**

Тема: «Почему важно учить иностранные языки».

Эссе (фрагмент): «Учить иностранные языки очень важно. Это помогает в путешествиях. Также помогает в работе. Многие люди учат английский. Я тоже учу английский. Это полезно...»

Выход (сокращённо):
```json
{
  "scores": {"structure": 4, "argument": 3, "examples": 2, "language": 5, "topic": 7},
  "overall": 4.2,
  "summary": "Тема раскрыта поверхностно, аргументы повторяются, нет конкретных примеров. Стоит развернуть один-два аргумента до полного абзаца с примером из жизни."
}
```

**Кейс 2. Сильное эссе:**

Тема: «Влияние удалённой работы на продуктивность».

Эссе на 600 слов с тезисом, тремя аргументами и контраргументом.

Выход (сокращённо):
```json
{
  "scores": {"structure": 9, "argument": 9, "examples": 8, "language": 8, "topic": 10},
  "overall": 8.8,
  "summary": "Сильная работа: чёткий тезис, контраргумент проработан, примеры конкретные (Buffer, GitLab). Можно усилить за счёт более вариативной лексики — несколько ключевых слов повторяются 3-4 раза."
}
```

## Калькулятор стоимости

Эссе на 500 слов — примерно 1 200 токенов вход (system + рубрика + текст), 800 токенов выход (детальный JSON-фидбэк).

| Параметр | Значение |
|---|---|
| Модель | GPT-5.4 |
| Цена входа | 200 ₽ / 1М токенов |
| Цена выхода | 800 ₽ / 1М токенов |
| **1 эссе** | **~1,0 ₽** |
| **1 000 эссе** | **~480 ₽** (с учётом более коротких работ в среднем) |
| 4 000 эссе/мес (1k студентов × 1 задание/нед) | ~1 920 ₽ |

Если бы тех же 4 000 эссе проверял ассистент — 60-80к ₽/мес. Экономия в 30-40 раз. И это без учёта того, что ассистенту нужны выходные.

## Что улучшить дальше

1. **Prompt caching на рубрику.** Рубрика и system prompt одни и те же на курсе — закэшируй (V2 Brikko), снижение стоимости input на 50-60% при объёме от 30 эссе в день.
2. **Streaming для UX в кабинете.** Преподаватель открывает эссе и видит, как фидбэк появляется построчно за 3-5 секунд вместо ожидания 8-12 секунд полного ответа.
3. **Anti-cheat через детектор LLM-генерации.** Если подозрение, что эссе сгенерировано — добавь второй проход с моделью на детекцию AI-текста (OpenAI text classifier или open-source Ghostbuster). При высокой вероятности — отметь работу для ручной проверки.

# Анализ договоров с обезличиванием ПДн через PII-маскинг

## Зачем это нужно

Юрист в средней фирме просматривает 10-15 договоров в день: проверяет рисковые формулировки, выделяет ключевые условия (срок, ответственность, штрафы, неустойка), сверяет с шаблоном. На каждый договор уходит 30-60 минут. LLM делает это за 10 секунд — но в тексте договора есть ФИО сторон, паспортные данные, ИНН физлиц, адреса. Отправить такой текст в OpenAI напрямую — нарушение 152-ФЗ и риски по договору с клиентом.

Решение — Brikko PII-маскинг: перед отправкой в провайдера движок находит персональные данные регэкспами + NER-моделью и заменяет их на токены вида `<NAME_1>`, `<PASSPORT_1>`, `<INN_1>`. LLM работает с обезличенным текстом, ответ возвращается, токены автоматически подставляются обратно. Внешний провайдер видит только `<NAME_1> заключил договор с <NAME_2> о передаче <ADDRESS_1>`.

## Какая модель и почему

**Claude Sonnet 4.6** — лучший баланс точности и цены для юр-задач на русском. Длинный контекст (200к), даёт развёрнутые обоснования рисков, реже додумывает несуществующие пункты, чем GPT-5. На договорах 5-15 страниц вписывается без чанкования.

Для договоров от 30 страниц — **Claude Opus 4.7** (дороже в 5 раз, но reasoning по сложным конструкциям заметно лучше). Для типовых договоров поставки/услуг можно взять GPT-5.4 — дешевле на 30-40%, точность сопоставима.

## Готовый код

```python
from openai import OpenAI

client = OpenAI(
    api_key="brk_live_...",
    base_url="https://api.brikko.ru/v1",
)

SYSTEM_PROMPT = """Ты юрист-аналитик. Анализируешь договор и возвращаешь:
1. Тип договора и стороны.
2. Ключевые условия: срок, цена, порядок оплаты, ответственность.
3. Рисковые пункты с цитатой и обоснованием риска.
4. Отсутствующие стандартные защитные оговорки.

Формат — markdown с разделами. Цитируй пункты дословно с номером.
"""

def analyze_contract(text: str) -> str:
    response = client.chat.completions.create(
        model="claude-sonnet-4-6",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": f"Договор:\n\n{text}"},
        ],
        temperature=0.2,
        max_tokens=2000,
        extra_headers={
            "X-Brikko-PII-Mode": "strict",  # ON по умолчанию для Pro+
        },
    )
    return response.choices[0].message.content


if __name__ == "__main__":
    contract = open("contract.txt", encoding="utf-8").read()
    print(analyze_contract(contract))
```

## Примеры

**Кейс 1. Что видит провайдер vs что видишь ты:**

Исходный текст:
> «Иванов Иван Петрович, паспорт 4500 123456, проживающий по адресу г. Москва, ул. Тверская, д. 5, кв. 12, заключил договор с ООО "Ромашка" в лице директора Сидорова Сергея Ивановича...»

Что уходит в Anthropic после PII-маскинга:
> «<NAME_1>, паспорт <PASSPORT_1>, проживающий по адресу <ADDRESS_1>, заключил договор с <ORG_1> в лице директора <NAME_2>...»

Что возвращается тебе (после обратной подстановки):
> «Договор заключён между Ивановым Иваном Петровичем и ООО "Ромашка". Риск п. 4.2: одностороннее право расторжения только у заказчика без обязательства возмещения...»

**Кейс 2. Реальный фрагмент анализа:**

Вход — договор оказания услуг на 8 страниц, вход 6 200 токенов после PII-маскинга.

Выход (фрагмент):
```markdown
## Рисковые пункты

**п. 5.3 — неограниченная ответственность исполнителя.**
Цитата: "Исполнитель несёт ответственность за все прямые и косвенные убытки
заказчика без ограничения суммой договора."
Риск: при цене договора 500к убытки могут составлять миллионы.
Стандартная оговорка — лимит = сумма договора.

**п. 7.1 — отсутствует force-majeure.**
В договоре нет освобождения от ответственности при обстоятельствах
непреодолимой силы. Рекомендую добавить стандартную формулировку из ГК ст. 401.
```

## Калькулятор стоимости

Договор на 10 страниц — примерно 6 000 токенов вход, 1 500 токенов выход анализа.

| Параметр | Значение |
|---|---|
| Модель | Claude Sonnet 4.6 |
| Цена входа | 240 ₽ / 1М токенов |
| Цена выхода | 1 200 ₽ / 1М токенов |
| **1 договор** | **~3,7 ₽** |
| 100 договоров в месяц | ~370 ₽ |
| 1 000 договоров | ~3 700 ₽ |
| **Стоимость для калькулятора (среднее с маскингом и overhead)** | ~0,98 ₽ за 1 договор |

Сравни с часом работы юриста (3 000-8 000 ₽) — экономия двузначная.

## Что улучшить дальше

1. **Prompt caching на шаблон.** Если ты прогоняешь однотипные договоры (например, типовые поставки), вынеси «эталонный» договор в system prompt и закэшируй — анализ ускорится и подешевеет на 40-50%.
2. **Streaming для длинных договоров.** При 30+ страницах Sonnet может думать 15-25 секунд. Включи `stream=True` и показывай результат по мере готовности — UX в кабинете заметно лучше.
3. **PII-аудит лог.** В Brikko Pro+ доступен аудит-лог: какие токены маскировались, в какие исходные значения подставлялись обратно. Полезно для отчётов в ФСТЭК и обоснования compliance перед клиентом.
